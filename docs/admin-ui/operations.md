# 管理操作と結果の確認

管理操作の影響確認から実行、通信停止・資源解放を含む結果確認までを定める。管理者の切り替え時の情報分離と状態の取得・表示は [状態表示仕様](state.md)に従う。

共通の前提・用語・利用場面は [共通仕様](../platform/overview.md) に従う。

## 管理者の操作

管理者は、管理 UI から許可されたルーム・参加端末・設定の操作を要求する。要求を受ける C-Plane は、画面上の表示やボタンの状態にかかわらず、[認証・認可仕様](../auth/authorization.md)に従って管理者と対象への操作権限を確認する。

| 操作 | 対象と動作 |
|---|---|
| ルームの作成 | ルーム情報を作成する。この時点では SFU の通信資源を確保しない |
| ルーム設定の変更 | 通話時間の上限など、変更を許可された設定を更新する |
| ルームの削除 | ルームを削除し、参加中の参加端末の通信を終了して関連資源を解放する |
| 参加端末の除外 | 選択した参加端末の通信を終了する。同じ参加者の別の参加端末まで無条件に終了しない |
| 利用権限の変更・失効 | 対象の参加・発行・購読・データ通信などの権限を、管理者に許可された範囲で変更する |
| SFU の drain 開始 | 対象 SFU への新しいルーム割り当てを停止し、既存仕様に従って移行と退役を進める |

### 対象と影響を確認して実行する

管理 UI は、実行を要求する前に対象と影響範囲を表示し、表示名に加えてルーム・参加者・参加端末の識別情報で対象を確かめられるようにする。ルーム削除、参加端末の除外、通信停止を伴う権限変更、SFU の drain などでは、管理者が影響するルーム・参加端末・通信と、終了・移行の条件を確認してから実行を要求できるようにする。

設定変更では、管理 UI が変更前後の値、許容範囲、適用対象と適用時点を示し、既存の通話とその後の通話のどちらに変更が及ぶかを確認できるようにする。変更を要求された C-Plane は、画面から指定できる値でも、プロトコル要件・権限・資源上限に従って検証する。具体的な編集項目と適用条件は各設定の設計で定める。

画面での確認から実行までに、退出、再接続、権限変更、ルーム削除、SFU 移行が起きることがある。C-Plane は実行時に画面で確認した対象を現在の状態と照合し、その時点の権限を確認して、古い画面の要求が新しい接続・割り当てに及ぶのを防ぐ。別の管理者による変更と競合した場合も、管理 UI が成功として表示するには変更結果の確認を要する。

### 完了を確認し、結果不明を照合する

要求後、管理 UI は操作の受け付け、設定・権限の反映、通信停止、資源解放を別々に表示する。例えば権限失効が決定しても、通信停止を確認するまでは停止完了と表示しない。操作結果は処理中・完了・失敗・結果不明を区別し、不明な場合は現在の状態と照合する。再試行や画面の再読み込みをきっかけに同じ操作を無条件に繰り返さない。

### ルーム削除の受け付けから完了まで

C-Plane がルーム削除を受け付けた時点で、そのルームへの新しい参加と通常の利用・変更操作を拒否する。通信停止・資源解放に必要な管理処理は継続し、停止・解放とその照合・回収に使う管理情報は処理完了まで保持する。

停止・解放が失敗したり結果が不明になったりした場合は、保持した管理情報で対象を追跡し、再確認・回収できるようにする。結果不明の資源は [共通の資源管理](../platform/resources.md#結果が不明な場合の照合と回収) に従い、解放を確認するまで計上する。管理 UI は削除の受け付けを表示し、対象通信の停止と関連資源の解放が両方確認された時点で削除完了を表示する。具体的な削除処理の順序と内部の状態管理方法は固定しない。

### 参加端末の除外・権限失効・SFU の drain

参加端末を除外した場合や通信権限が失効した場合は、それぞれに定められた期限内に対象通信を停止し、対象の Browser SDK へ終了理由を通知する。除外は [Signaling の参加・退出](../signaling/session.md#参加退出)、失効の反映は [認可仕様](../auth/authorization.md#有効期限権限変更失効の反映)に従う。自動再接続で終了を取り消さず、その後の再参加要求は現在の参加権限に従って判断する。除外だけで恒久的な参加禁止にはしない。

SFU の drain が始まったら、管理 UI は対象、開始状態、退役期限、移行の進行と結果を確認できるようにする。途中参加・再接続・移行の再試行でも退役期限は維持する。旧接続を維持できない場合の一時中断や自動再接続は [SFU の障害時の復旧条件](../sfu/placement.md#準備失敗退役期限到達障害時の復旧)に従う。

### 操作の制限と監査

管理権限によって、参加端末のカメラ・マイクを利用者の許可なく取得・有効化しない。
E2EE の本文を閲覧したり、秘密鍵・復号鍵を取得したりする操作は提供しない。

管理操作は、要求した管理者、対象、操作内容、受け付け・適用・停止などの結果を追跡できるように記録する。
資格情報、暗号鍵、メディア・データ本文を記録しない。
画面構成、具体的な API、管理者の認証方式と権限名は、この段階では固定しない。

## 自作範囲・既存実装の利用

管理 UI は TypeScript で実装する。
管理操作と状態取得は C-Plane の管理 API を通じて行う。
D-Plane の内部状態や管理用ソケットを、ブラウザーから直接操作する構成にしない。

管理 UI は、対象・変更内容・影響範囲を表示し、管理者の確認を経て実行を要求する画面を実装する。
要求後は、受け付け・適用・停止・解放の進行と、失敗・結果不明を追跡して表示する。

管理者の認証、操作・閲覧の認可、設定値の検証、変更の確定は C-Plane が行う。
管理 UI でも入力検証と操作可能範囲の表示を行うが、サーバー側の検証を省略しない。
画面の状態を変更しただけで、サーバー側の権限や処理結果を変更できないようにする。

画面構築、ルーティング、フォーム、一覧・グラフ、状態取得、通知、入力スキーマ検証には既存ライブラリを利用できる。
共通化できる API 通信・型・検証処理は再利用する。
管理 UI は管理 API を利用するアプリケーションとし、通話用の React SDK への依存は必須としない。
管理 UI のためだけに React SDK へ管理機能を追加せず、共通化の利点がある処理だけを再利用し、不要な共通抽象化を作らない。
利用する UI フレームワーク、ライブラリ、API クライアントの構成は、この段階では固定しない。

採用するライブラリ・基盤のバージョン、設定、依存機能、確認した動作環境を記録する。
実装と検証は、[実装・検証の共通方針](../platform/verification.md#実装検証の共通方針)に従う。

## セキュリティ

管理 UI と管理 API の通信は HTTPS / WSS で保護し、接続先を検証する。
接続失敗を理由に平文通信へ切り替えない。
管理者の認証、資格情報の更新・失効、接続の保護は、認証・認可仕様に従う。

管理 API は、操作・状態取得・検索・通知購読・監査記録の取得ごとに、現在の管理権限と対象範囲を確認する。
管理画面へログインできることだけで、すべてのルーム・参加端末・設定へのアクセスを許可しない。
URL、API の引数、画面の状態を変更しても、許可範囲を超えて取得・操作できないようにする。

管理者用の資格情報を、参加者用トークンや内部サービス用の資格情報と無条件に流用しない。
認証情報を URL・ログ・診断・エラー報告へ露出させない。
ブラウザーが自動送信する資格情報を使う場合は、第三者サイトからの不正な接続・操作を防ぐ。
Origin の確認だけで、管理者の認証や操作の認可を済ませない。

画面で確認した対象・設定と、実行時の対象・状態を対応付ける。
操作の確認画面を表示したことだけで、その後の権限確認や状態確認を省略しない。
権限失効、接続の引き継ぎ、他の管理者の変更と競合した場合は、既存仕様の確定順序に従って判断する。
反映済みの失効を、古い画面・資格情報・権限情報で覆さない。

削除・除外・権限変更・drain の要求や再試行は、対象と操作を識別して処理する。
応答の消失や重複要求で、別の対象への操作や意図しない追加処理を行わない。
ルーム削除では、通信停止・資源解放を追跡する管理情報を処理完了まで保持する。
失敗・結果不明を完了として表示せず、共通の資源管理に従って照合・回収する。

ルーム名、参加者名、論理チャネル名、エラー情報、監査記録などを、信頼できない入力として扱う。
表示時に実行可能な HTML やスクリプトとして解釈しない。
入力値の形式・サイズ・範囲は、管理 UI と C-Plane のそれぞれで検証する。
UI ライブラリを利用する場合も、入力・表示の検証を省略しない。

サーバー側の署名鍵、TURN の共通秘密情報、内部サービス用の資格情報、E2EE の秘密鍵・復号鍵を管理 UI に渡さない。
状態確認のために、メディア・DataChannel の本文やパケット全体を取得しない。
管理権限によって E2EE を解除したり、参加端末のカメラ・マイクを利用者の許可なく有効化したりする機能を提供しない。

一覧・検索・統計・履歴・通知・再試行には、件数、処理量、保持量、待機時間の上限を設ける。
管理 UI からの大量要求によって、通信処理や失効反映を妨げない。
過負荷時にも認証・認可を省略しない。

監査記録は、認証した管理者、対象、操作、結果、適用・停止との対応を確認できるようにする。
監査記録の閲覧にも権限を適用し、保持期限を設ける。
資格情報、暗号鍵、メディア・データ本文を記録しない。

## 受け入れ条件

実際の管理 UI、管理 API、C-Plane、D-Plane、Browser SDK を組み合わせて検証する。
通常操作に加え、複数管理者の同時操作、応答・通知の欠落や遅延、権限失効、再接続、再起動、SFU 移行を確認する。

| 試験対象 | 確認する結果 |
|---|---|
| 管理者の認証・認可 | 操作・閲覧・検索・通知・監査取得に対象ごとの権限を適用する。URL・引数・画面状態の変更で制限を迂回できない |
| 操作前の確認 | 対象、変更内容、影響範囲を確認できる。表示名だけで参加端末やルームを取り違えない |
| ルーム作成 | ルーム情報だけを作成し、参加前に SFU の通信資源を確保しない |
| 設定変更 | 変更前後の値、適用対象・時点を示す。不正値や未許可の変更を C-Plane が拒否する |
| ルーム削除 | 受け付け後は新しい参加・通常操作を拒否する。停止・解放の管理情報を保持し、両方を確認するまで削除完了と表示しない |
| 削除中の障害 | 通信停止・資源解放が失敗・結果不明でも対象を追跡し、再確認・回収できる。解放未確認の資源を空きとして扱わない |
| 参加端末除外・権限失効 | 対象範囲だけに適用し、期限内に必要な通信を停止する。別の参加端末まで無条件に終了せず、自動再接続で終了を取り消さない |
| SFU の drain | 新しいルーム割り当てを停止し、期限・移行・中断・復旧結果を表示する。再試行で退役期限を延長しない |
| 操作結果の追跡 | 受け付け・適用・停止・解放を区別する。応答消失を成功・失敗と断定せず、再試行で操作を重複実行しない |
| 並行する変更 | 権限失効、再接続、移行、他の管理者の操作と競合しても、既存の確定順序を守る。古い操作で新しい資源を変更・終了しない |
| 入力・表示の保護 | 不正な形式・サイズ・値を拒否する。名前・エラー・監査記録などを実行可能な HTML やスクリプトとして描画しない |
| 資格情報と機密情報 | URL・公開状態・ログ・診断・監査へ秘密情報を露出させない。E2EE の鍵・本文やパケット全体を取得しない |
| 監査 | 管理者、対象、操作、結果、適用・停止の対応を追跡できる。閲覧権限と保持期限を適用する |

### 共通の検証方法と結果の記録

管理 UI の表示だけでなく、C-Plane・D-Plane の状態と実際の通信を確認する。
失効通知の受信や停止要求の受け付けだけで、通信停止を確認済みとは扱わない。
結果不明からの照合・回収後に、画面の表示も確認結果と一致することを検証する。

性能試験では、ルーム数、参加端末数、同時管理者数、更新頻度、検索・履歴の取得量、通知量を固定する。
表示・操作の応答時間、CPU・メモリ、API 負荷、保持状態を測定する。
共通仕様の通信負荷を併用し、管理 UI の取得・更新による音声・映像への影響と、失効反映時間を確認する。
合否基準は試験前に定め、測定完了と目標達成を区別する。
過負荷時も、認証・認可や失効の反映期限を緩めない。

検証には、共通の実装・検証方針を適用する。

| 検証方法 | 重点対象 |
|---|---|
| TLA+ によるモデル検査 | 管理操作と権限失効の競合、削除・停止・解放、状態同期、管理者切り替えと遅延応答 |
| Fuzzing | 管理 API・通知・操作結果の入力、形式・サイズ・対象、表示に使う外部入力 |
| Property-based Testing | 操作・通知・再試行・管理者切り替えの列、古い結果の排除、表示状態と資源計数の整合 |
| 形式的な証明の評価 | 対象・操作結果の対応、更新順序、管理者間の情報分離などの数学モデル・性質について、Lean 4 などの適合性を評価する |

数学モデルの検証と、TypeScript の実装コードの検証を区別する。
Verus・Aeneas を、TypeScript 実装の直接検証手段として扱わない。
既存ライブラリ内部の再検証は一律に要求しないが、設定・呼び出し・入力・結果の扱いは検証対象とする。
モデル検査、Fuzzing、静的解析、統合試験の結果と保証範囲を区別する。

Chrome・Firefox・Safari で、実際の画面操作・状態更新・認証連携を確認する。
採用した UI フレームワーク固有の再描画・ライフサイクルでも、重複操作や情報の混入を起こさないことを確認する。
通話用 React SDK に依存しない構成を認め、管理 UI のための不要な管理機能・共通抽象化を React SDK に追加しない。

結果には、ブラウザー・UI・サーバー・依存ライブラリのバージョン、権限設定、負荷、障害条件、更新間隔、期限・上限、検証範囲と観測結果を記録する。
画面構成、統計項目、更新間隔、履歴保持期間の具体値は、後続の設計で定める。
