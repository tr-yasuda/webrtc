# サプライチェーン対策

依存関係や開発ツールの侵害が、開発端末や CI でのコード実行や、本番環境の不正な変更につながるリスクを抑える。

## 依存関係と CI

- CI は pnpm と Cargo のロックファイルを使う。依存を追加・更新する PR では、直接依存と間接依存の取得元、新たに実行されるインストール・ビルドスクリプト、Cargo の手続きマクロをレビューする。開発ツールの取得元やバージョンの変更にも同じ確認を行う。
- pnpm は依存の新規解決とロックファイルの検証に 24 時間の待機期間を適用し、公開時刻を確認できない版も拒否する。緊急修正で待機を省く場合は、対象パッケージとバージョン、理由を PR に記載してレビューを受ける。
- pnpm は未審査の依存のインストールスクリプトを検出したらセットアップを失敗させる。実行が必要なスクリプトは、内容と必要性を確認し、パッケージとバージョンを指定して許可する。
- 外部 Action と外部の再利用ワークフローは、配布元で確認した完全なコミット SHA で固定する。CI は zizmor のオフライン検査で SHA 未固定などの問題を検出する。配布元と実行内容は参照を更新する PR で確認する。Action が実行時に取得するツールも、設定できる場合はバージョンを固定する。

## GCP の本番配備

- PR 検証、通常 CI、成果物のビルドおよび検証環境への配備には、本番を変更する権限を付与しない。GCP は Workload Identity Federation でリポジトリ ID、保護されたブランチ、所定のワークフローと本番環境を確認する。本番用の短期資格情報は承認済みの配備ジョブに限って発行する。
- 本番の配備ジョブは、依存パッケージのインストールや成果物の再ビルドを行わない。配備用と実行用の権限を分け、配備用の権限で認証・承認の条件や成果物の出所を証明する設定を変更できないようにする。
- 担当者は、検証環境で確認した成果物のダイジェストと、本番に適用する Terraform プランを承認する。配備時は、成果物の出所が所定のビルドと対象コミットに結び付くこと、成果物とプランが承認時と一致することを検証する。出所が不明、承認がない、または承認後に内容が変わった場合は反映を拒否する。切り戻しも承認された成果物を対象とする。

## 受け入れ条件

- 現行の依存でローカルのセットアップと CI の検査が通る。新規解決時の公開直後の依存、未審査のインストールスクリプト、SHA 未固定の外部 Action・再利用ワークフローは、それぞれ対応する検査で拒否される。
- GCP の初回公開前に、PR や通常 CI、所定外のワークフロー、承認前の配備ジョブが本番用資格情報を取得できないことを実環境で確認する。
- GCP の初回公開前に、承認済みの成果物とプランで配備できることと、出所不明の成果物、ダイジェストの不一致、プランの差し替えが拒否されることを確認する。
