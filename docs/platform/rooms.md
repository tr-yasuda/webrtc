# ルームと参加端末のライフサイクル

## ルーム・参加者・権限

ルームは正本 ID であるルーム ID で識別する。参加 JWT では、Project 内で一意な `Room.name` を対象 Room の指定に使う。参加者はルーム内で一意の参加者 ID で識別する。同じ参加者が複数の端末から参加した場合は端末ごとに扱い、既存の参加端末が接続を再確立しただけなら、新たな参加端末として登録しない。

未作成ルームへの初回参加には、`room.create` と `room.join` の両方を持つ参加 JWT を必要とする。`room.create` は `room.join` を自動的に許可せず、`room.create` 単独ではルームを作成も参加も確定しない。作成されたルームは明示的な削除まで保持し、削除時には参加中の全員の通信を終了する。同じ `ProjectId` と `Room.name` への並行した初回参加では、作成と SFU 割り当てを一意に確定する。初期提供では Management API によるルーム作成を行わない。

### 参加から資源の解放まで

ルームを作成した時点では SFU 上の通信資源を確保せず、最初の参加端末が参加したときに SFU を割り当てて確保する。最後の参加端末が退出したときは、[Signaling の参加・退出](../signaling/session.md#参加退出)で定める並行参加・再接続待ちの条件に従って通信資源を解放し、SFU の割り当てを解除する。割り当て解除後に再び参加端末が入ると、SFU を改めて割り当てるため、以前と異なる SFU に配置される場合がある。

通信断から退出と判断するまでの猶予は、[Signaling の再接続](../signaling/session.md#再接続)で定める。

### 通話時間の上限に達したとき

通話時間は、空のルームに最初の参加端末が参加した時点から計測し、途中参加・再接続・SFU 移行を経ても同じ起点を使う。ルームに通話時間の上限を設定した場合はこの計測値で終了時刻を決め、上限が未設定なら時間による終了は行わない。

通話時間の上限と SFU の退役期限は、初期設定では期限到達の 60 秒前に予告し、予告の時間は変更できる。途中参加などで予告時刻を過ぎている場合は、その時点で Browser SDK へ通知する。予告の画面表示は Browser SDK を利用するアプリケーションが決める。

通話時間の上限に達したら、ルーム情報を保持したまま全員の通話を終了し、通信資源を解放する。Browser SDK は終了理由を通知し、自動再接続しない。

### 操作権限と退出の対象

アプリケーションは、参加者に許可する操作を指定する。

| 権限 | 許可する操作 |
|---|---|
| `room.create` | 指定された未作成 `Room.name` を、最初の参加時に作成する |
| `room.join` | 指定された `Room.name` のルームへ参加 |
| 発行 | 自分の音声・カメラ映像・画面共有の発行 |
| 購読 | 同じルームで発行された音声・映像の購読 |
| データ送信 | 同じルームへの DataChannel によるデータ送信 |

アプリケーションは各権限を個別に設定できる。ルームの削除・設定変更・強制切断には、参加 JWT の権限とは別に Management API の ProjectUser 権限を使う。参加者が操作を要求すると、Signaling は信頼できるアプリケーションが署名した参加 JWT と現在のルーム・失効状態を確認し、許可されていない操作を拒否する。参加者は Client SDK の操作で自分の権限を増やせない。

通常の退出では、対象の参加端末の発行・購読・DataChannel の通信を終了する。同じ参加者の別の参加端末を含め、ほかの参加端末の通信は継続する。
