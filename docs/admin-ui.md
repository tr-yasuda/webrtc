# 管理 UI

共通の前提・用語・利用場面は [共通仕様](spec.md) に従う。

## 管理者の操作

管理 UI は、認証した管理者が、許可されたルーム・参加端末・設定を操作するために提供する。
操作は C-Plane を通じて実行する。画面上の表示やボタンの有効・無効だけで権限を判断しない。
認証と管理権限の確認は、認証・認可仕様に従う。

| 操作 | 対象と動作 |
|---|---|
| ルームの作成 | ルーム情報を作成する。この時点では SFU の通信資源を確保しない |
| ルーム設定の変更 | 通話時間の上限など、変更を許可された設定を更新する |
| ルームの削除 | ルームを削除し、参加中の参加端末の通信を終了して関連資源を解放する |
| 参加端末の除外 | 選択した参加端末の通信を終了する。同じ参加者の別の参加端末まで無条件に終了しない |
| 利用権限の変更・失効 | 対象の参加・発行・購読・データ通信などの権限を、管理者に許可された範囲で変更する |
| SFU の drain 開始 | 対象 SFU への新しいルーム割り当てを停止し、既存仕様に従って移行と退役を進める |

操作前に、対象と影響範囲を表示する。
ルーム削除、参加端末の除外、通信停止を伴う権限変更、SFU の drain などでは、影響するルーム・参加端末・通信と終了・移行条件を確認してから実行できるようにする。
表示名だけで対象を区別せず、ルーム・参加者・参加端末の識別情報を確認できるようにする。

設定変更では、変更前後の値、許容範囲、適用対象と適用時点を表示する。
既存の通話へ適用する変更と、その後の通話へ適用する変更を区別する。
画面から指定できる値でも、C-Plane がプロトコル要件・権限・資源上限に従って検証する。
具体的な編集項目と適用条件は、各設定の設計で定める。

操作の受け付け、設定・権限の反映、通信停止、資源解放を区別して表示する。
権限失効は、決定しただけで通信停止まで完了したとは表示しない。
処理中・完了・失敗・結果不明を区別し、結果不明の場合は現在の状態と照合する。
再試行や画面の再読み込みで、同じ操作を無条件に繰り返さない。

ルーム削除を C-Plane が受け付けた時点で、そのルームへの新しい参加と通常の利用・変更操作を許可しない。
通信停止・資源解放と、その照合・回収に必要な管理情報は、処理が完了するまで保持する。
停止・解放のための管理処理は継続できるようにし、通信停止や資源解放が失敗・結果不明でも、対象を追跡して再確認・回収できるようにする。
削除の受け付けと、対象通信の停止・関連資源の解放を確認した削除完了を区別する。
結果不明の資源を解放済みとは扱わず、共通の資源管理に従う。
具体的な削除処理の順序や内部の状態管理方法は、この段階では固定しない。

表示後に、対象の退出、再接続、権限変更、ルーム削除、SFU 移行が起きる場合を考慮する。
C-Plane は実行時に対象と権限・現在の状態を確認する。
古い画面からの操作で、新しい接続・割り当てを誤って終了・変更しない。
別の管理者による変更と競合した場合も、変更結果を確認せず成功と表示しない。

参加端末の除外や通信権限の失効では、既存仕様の期限内に対象通信を停止する。
終了理由を対象の Browser SDK へ通知し、自動再接続でその終了を取り消さない。
再参加を許可するかは現在の参加権限に従い、除外と恒久的な参加禁止を同一視しない。

SFU の drain では、対象、開始状態、退役期限、移行の進行と結果を確認できるようにする。
途中参加・再接続・移行の再試行で退役期限を延長しない。
旧接続を維持できない場合の一時中断や、自動再接続も既存の SFU 仕様に従う。

管理権限によって、参加端末のカメラ・マイクを利用者の許可なく取得・有効化しない。
E2EE の本文を閲覧したり、秘密鍵・復号鍵を取得したりする操作は提供しない。

管理操作は、要求した管理者、対象、操作内容、受け付け・適用・停止などの結果を追跡できるように記録する。
資格情報、暗号鍵、メディア・データ本文を記録しない。
画面構成、具体的な API、管理者の認証方式と権限名は、この段階では固定しない。

## 状態確認

管理 UI は、管理者が閲覧を許可された範囲で、ルーム・参加端末・通信・資源・管理操作の状態を表示する。
閲覧権限と変更権限を区別し、表示できることだけで操作を許可しない。

| 対象 | 確認できる内容 |
|---|---|
| ルーム | 設定、参加者数・参加端末数、通話の開始・終了状態、通話時間上限、SFU の割り当て |
| 参加端末 | 所属する参加者、参加・退出・再接続状態、現在の接続、終了理由 |
| 発行・購読 | 音声・カメラ映像・画面共有の対応、購読関係、希望品質と実際の転送品質 |
| エンコーディング | 集約した需要、停止・再開の要求状態、適用結果、非対応・失敗・待機の理由 |
| WebRTC Transport・DataChannel | 接続状態、選択経路、TURN 利用、配送方式、通信量、失敗・中断の理由 |
| 権限変更・失効 | 対象と変更内容、決定・反映の状態、反映期限、停止結果 |
| SFU | 担当ルーム、負荷・容量、drain 状態、退役期限、移行の進行・結果 |
| 資源管理 | 予約済み・使用中・解放待ち、上限、確保・解放の結果不明、隔離・照合・回収の状態 |
| 管理操作 | 要求した管理者、対象、受け付け・処理中・完了・失敗・結果不明、関連する監査記録 |

ルームの存在と SFU の通信資源の確保を分けて表示する。
空のルームが存在することだけで、SFU が割り当てられている、または通信資源を消費しているとは表示しない。
削除中のルームは、削除受け付け後の通信停止・資源解放を追跡できるようにする。

Signaling の接続状態と、WebRTC 通信の状態を区別する。
Signaling が切断しただけで、退出済み・通話終了と表示しない。
参加登録、WebRTC Transport 成立、E2EE 準備、実際の送受信・再生も分けて扱う。

表示する情報には、取得元と観測・更新時点を対応付ける。
サーバーが直接確認した状態と、参加端末からの報告を区別する。
SFU がパケットを送信したことだけで、参加端末での復号・デコード・再生まで成功したとは表示しない。
E2EE の状態も、サーバーが確認できる範囲と参加端末から報告された範囲を明示する。

情報を取得できない場合は、不明・未取得・更新停止を正常状態やゼロ件として表示しない。
以前の情報を表示する場合は、最後に確認した時点と、現在の状態を確認できていないことを示す。
古い表示だけで、操作を安全に実行できると判断しない。

現在の状態の取得と変更通知を組み合わせ、欠落・重複・順序逆転を検出して整合する表示へ戻せるようにする。
再接続、画面の再読み込み、SFU 移行後も、同じ参加端末・発行・購読を重複表示しない。
古い接続や操作の結果で、新しい状態を過去へ戻さない。
複数の取得元の情報が、同時点で互いに矛盾しない状態を示すか確認できない場合は、その制約を示す。

権限失効では、決定済み・反映待ち・通信停止確認済みを区別する。
通知の送信や受信だけで、反映・停止が完了したとは表示しない。
反映期限を超えた場合や結果不明の場合は、その対象と確認が必要な状態を示す。

資源の結果不明や解放待ちを、空き容量として表示しない。
状態区分と計数の範囲を明確にし、同じ資源の二重計上や、解放未確認の資源の計上漏れを防ぐ。
隔離・回収が必要な対象を、関連するルーム・接続・操作から追跡できるようにする。

通信統計は、対象、計測期間、単位、集計範囲を示す。
参加端末・発行・購読・SFU の統計を混同せず、欠測をゼロとして集計しない。
CPU・メモリ・帯域、遅延・損失、再送、キューなど、運用判断に必要な情報を表示する。
メディア本文や DataChannel 本文を取得して状態確認を行わない。

一覧・検索・詳細表示・変更通知・監査記録の取得にも、対象ごとの閲覧権限を適用する。
権限変更で閲覧できなくなった情報を、遅延した応答や再接続で再び表示しない。
資格情報、秘密鍵、復号鍵、TURN の共通秘密情報を表示しない。

取得・更新頻度、一覧件数、履歴、通知待ちには上限を設ける。
大量のルームや参加端末がある場合も、状態確認によって通信処理や失効反映を妨げない。
画面構成、統計項目の詳細、更新間隔、履歴の保持期間は、後続の設計で定める。

## 自作範囲・既存実装の利用

管理 UI は TypeScript で実装する。
管理操作と状態取得は C-Plane の管理 API を通じて行う。
D-Plane の内部状態や管理用ソケットを、ブラウザーから直接操作する構成にしない。

| 実装する部分 | 責務 |
|---|---|
| 管理操作の画面 | 対象・変更内容・影響範囲の表示、確認、実行要求 |
| 状態表示 | ルーム・参加端末・通信・資源・移行・管理操作の状態表示 |
| 状態同期 | 現在の状態と変更通知の対応、欠落・重複・順序逆転、再取得 |
| 操作結果の追跡 | 受け付け・適用・停止・解放、失敗・結果不明の表示 |
| 権限に応じた表示 | 閲覧・操作できる範囲の反映、権限変更後の表示更新 |
| 診断・監査の表示 | 対象と時点を確認できる統計、関連する操作・監査記録への対応 |

管理者の認証、操作・閲覧の認可、設定値の検証、変更の確定は C-Plane が行う。
管理 UI でも入力検証と操作可能範囲の表示を行うが、サーバー側の検証を省略しない。
画面の状態を変更しただけで、サーバー側の権限や処理結果を変更できないようにする。

ルーム・接続・権限・資源の状態は、それぞれを管理するコンポーネントから C-Plane を通じて取得する。
管理 UI に、独立した権限判断、資源計上、失効期限の管理を重複実装しない。
表示用に変換・集計した後も、取得元・観測時点・不明状態・計数範囲が分かるようにする。

管理者のログインは、認証・認可仕様で選定する基盤と連携する。
管理 UI に独自の利用者管理や認証基盤を重複実装しない。
サーバー側の署名鍵、TURN の共通秘密情報、内部サービス用の資格情報、E2EE の秘密鍵・復号鍵を保持させない。

画面構築、ルーティング、フォーム、一覧・グラフ、状態取得、通知、入力スキーマ検証には既存ライブラリを利用できる。
共通化できる API 通信・型・検証処理は再利用する。
管理 UI は管理 API を利用するアプリケーションとし、通話用の React SDK への依存は必須としない。
管理 UI のためだけに React SDK へ管理機能を追加せず、共通化の利点がある処理だけを再利用し、不要な共通抽象化を作らない。
利用する UI フレームワーク、ライブラリ、API クライアントの構成は、この段階では固定しない。

ライブラリが管理する取得結果、キャッシュ、再試行、通知購読、履歴にも上限と解放条件を設ける。
再描画・画面遷移・再接続で、重複した操作要求や通知購読を生成しない。
画面を閉じても、サーバー側の処理の取り消しや完了は別に確認する。
処理が継続する場合は、再表示後に現在の結果を照合できるようにする。

監視・統計・監査の保管や集計には既存基盤を利用できる。
その場合も、情報の取得元、更新時点、欠測、閲覧権限、保持期限を確認する。
既存基盤へ秘密情報やメディア・データ本文を送らない。

採用するライブラリ・基盤のバージョン、設定、依存機能、確認した動作環境を記録する。
実装と検証は、共通仕様の「実装・検証の共通方針」に従う。

## セキュリティ

管理 UI と管理 API の通信は HTTPS / WSS で保護し、接続先を検証する。
接続失敗を理由に平文通信へ切り替えない。
管理者の認証、資格情報の更新・失効、接続の保護は、認証・認可仕様に従う。

管理 API は、操作・状態取得・検索・通知購読・監査記録の取得ごとに、現在の管理権限と対象範囲を確認する。
管理画面へログインできることだけで、すべてのルーム・参加端末・設定へのアクセスを許可しない。
URL、API の引数、画面の状態を変更しても、許可範囲を超えて取得・操作できないようにする。

管理者用の資格情報を、参加者用トークンや内部サービス用の資格情報と無条件に流用しない。
認証情報を URL・ログ・診断・エラー報告へ露出させない。
ブラウザーが自動送信する資格情報を使う場合は、第三者サイトからの不正な接続・操作を防ぐ。
Origin の確認だけで、管理者の認証や操作の認可を済ませない。

画面で確認した対象・設定と、実行時の対象・状態を対応付ける。
操作の確認画面を表示したことだけで、その後の権限確認や状態確認を省略しない。
権限失効、接続の引き継ぎ、他の管理者の変更と競合した場合は、既存仕様の確定順序に従って判断する。
反映済みの失効を、古い画面・資格情報・権限情報で覆さない。

削除・除外・権限変更・drain の要求や再試行は、対象と操作を識別して処理する。
応答の消失や重複要求で、別の対象への操作や意図しない追加処理を行わない。
ルーム削除では、通信停止・資源解放を追跡する管理情報を処理完了まで保持する。
失敗・結果不明を完了として表示せず、共通の資源管理に従って照合・回収する。

ルーム名、参加者名、論理チャネル名、エラー情報、監査記録などを、信頼できない入力として扱う。
表示時に実行可能な HTML やスクリプトとして解釈しない。
入力値の形式・サイズ・範囲は、管理 UI と C-Plane のそれぞれで検証する。
UI ライブラリを利用する場合も、入力・表示の検証を省略しない。

取得結果、キャッシュ、変更通知は、認証した管理者と閲覧可能な範囲に対応付ける。
ログアウト、管理者の切り替え、閲覧権限の失効後に、以前の情報を別の利用者へ表示しない。
処理中の API リクエストと通知購読も、要求・通知購読を開始した管理者と、その認証状態に対応付ける。
管理者 A の操作中にログアウトし、管理者 B がログインした場合も、A の遅延応答や通知によって B の表示・キャッシュ・操作結果を変更しない。
要求や通知購読の中止が間に合わない場合も、以前の管理者に対応する結果を新しい管理者の画面や状態へ適用しない。
具体的なキャッシュライブラリや管理方法は、この段階では固定しない。
遅延した応答、通知、画面の再表示によって、閲覧できなくなった情報を再表示しない。
ブラウザーに既に表示・取得された情報の全コピーを、確実に消去できるとは保証しない。

C-Plane に接続できない場合は、確認済み情報の時点と更新停止を表示する。
古い情報を現在の権限や操作結果として扱わない。
認証・権限を必要な期限内に確認できない場合の操作拒否は、認証・認可仕様に従う。
画面を閉じたり通信が切れたりしても、受け付け済みの管理処理の取り消しは別に確認する。

サーバー側の署名鍵、TURN の共通秘密情報、内部サービス用の資格情報、E2EE の秘密鍵・復号鍵を管理 UI に渡さない。
状態確認のために、メディア・DataChannel の本文やパケット全体を取得しない。
管理権限によって E2EE を解除したり、参加端末のカメラ・マイクを利用者の許可なく有効化したりする機能を提供しない。

一覧・検索・統計・履歴・通知・再試行には、件数、処理量、保持量、待機時間の上限を設ける。
管理 UI からの大量要求によって、通信処理や失効反映を妨げない。
過負荷時にも認証・認可を省略しない。

監査記録は、認証した管理者、対象、操作、結果、適用・停止との対応を確認できるようにする。
監査記録の閲覧にも権限を適用し、保持期限を設ける。
資格情報、暗号鍵、メディア・データ本文を記録しない。

## 受け入れ条件

実際の管理 UI、管理 API、C-Plane、D-Plane、Browser SDK を組み合わせて検証する。
通常操作に加え、複数管理者の同時操作、応答・通知の欠落や遅延、権限失効、再接続、再起動、SFU 移行を確認する。

| 試験対象 | 確認する結果 |
|---|---|
| 管理者の認証・認可 | 操作・閲覧・検索・通知・監査取得に対象ごとの権限を適用する。URL・引数・画面状態の変更で制限を迂回できない |
| 操作前の確認 | 対象、変更内容、影響範囲を確認できる。表示名だけで参加端末やルームを取り違えない |
| ルーム作成 | ルーム情報だけを作成し、参加前に SFU の通信資源を確保しない |
| 設定変更 | 変更前後の値、適用対象・時点を示す。不正値や未許可の変更を C-Plane が拒否する |
| ルーム削除 | 受け付け後は新しい参加・通常操作を拒否する。停止・解放の管理情報を保持し、両方を確認するまで削除完了と表示しない |
| 削除中の障害 | 通信停止・資源解放が失敗・結果不明でも対象を追跡し、再確認・回収できる。解放未確認の資源を空きとして扱わない |
| 参加端末除外・権限失効 | 対象範囲だけに適用し、期限内に必要な通信を停止する。別の参加端末まで無条件に終了せず、自動再接続で終了を取り消さない |
| SFU の drain | 新しいルーム割り当てを停止し、期限・移行・中断・復旧結果を表示する。再試行で退役期限を延長しない |
| 操作結果の追跡 | 受け付け・適用・停止・解放を区別する。応答消失を成功・失敗と断定せず、再試行で操作を重複実行しない |
| 並行する変更 | 権限失効、再接続、移行、他の管理者の操作と競合しても、既存の確定順序を守る。古い操作で新しい資源を変更・終了しない |
| 情報の取得元と時点 | サーバーの直接確認と参加端末報告を区別する。パケット送信だけで参加端末の復号・再生成功と表示しない |
| 未取得・更新停止・結果不明 | 正常・ゼロ件・完了として表示しない。以前の情報を示す場合は、最後の確認時点と未確認の状態を示す |
| 状態同期 | 欠落・重複・順序逆転、画面再表示、再接続でも整合する状態へ戻る。対象の重複表示や過去状態への巻き戻りを防ぐ |
| 資源と統計 | 予約・使用・解放待ち・隔離の計数範囲を維持する。欠測をゼロとせず、対象・期間・単位・集計範囲を示す |
| 管理者の切り替え | A の要求・通知を遅延させてログアウトし、B がログインしても、A の情報で B の表示・キャッシュ・操作結果を変更しない |
| リクエスト中止との競合 | 中止が間に合わず旧管理者の応答・通知が届いても適用しない。画面の破棄だけでサーバー側の処理を取り消したとは扱わない |
| 閲覧権限の失効 | 取得済みの情報と処理中の応答・通知を含め、未許可の情報を再表示しない |
| 入力・表示の保護 | 不正な形式・サイズ・値を拒否する。名前・エラー・監査記録などを実行可能な HTML やスクリプトとして描画しない |
| 資格情報と機密情報 | URL・公開状態・ログ・診断・監査へ秘密情報を露出させない。E2EE の鍵・本文やパケット全体を取得しない |
| 資源制限 | 一覧・検索・統計・履歴・通知・再試行を有限に保つ。画面遷移や再接続で要求・通知購読・保持状態を増殖させない |
| 監査 | 管理者、対象、操作、結果、適用・停止の対応を追跡できる。閲覧権限と保持期限を適用する |

管理 UI の表示だけでなく、C-Plane・D-Plane の状態と実際の通信を確認する。
失効通知の受信や停止要求の受け付けだけで、通信停止を確認済みとは扱わない。
結果不明からの照合・回収後に、画面の表示も確認結果と一致することを検証する。

性能試験では、ルーム数、参加端末数、同時管理者数、更新頻度、検索・履歴の取得量、通知量を固定する。
表示・操作の応答時間、CPU・メモリ、API 負荷、保持状態を測定する。
共通仕様の通信負荷を併用し、管理 UI の取得・更新による音声・映像への影響と、失効反映時間を確認する。
合否基準は試験前に定め、測定完了と目標達成を区別する。
過負荷時も、認証・認可や失効の反映期限を緩めない。

検証には、共通の実装・検証方針を適用する。

| 検証方法 | 重点対象 |
|---|---|
| TLA+ によるモデル検査 | 管理操作と権限失効の競合、削除・停止・解放、状態同期、管理者切り替えと遅延応答 |
| Fuzzing | 管理 API・通知・操作結果の入力、形式・サイズ・対象、表示に使う外部入力 |
| Property-based Testing | 操作・通知・再試行・管理者切り替えの列、古い結果の排除、表示状態と資源計数の整合 |
| 形式的な証明の評価 | 対象・操作結果の対応、更新順序、管理者間の情報分離などの数学モデル・性質について、Lean 4 などの適合性を評価する |

数学モデルの検証と、TypeScript の実装コードの検証を区別する。
Verus・Aeneas を、TypeScript 実装の直接検証手段として扱わない。
既存ライブラリ内部の再検証は一律に要求しないが、設定・呼び出し・入力・結果の扱いは検証対象とする。
モデル検査、Fuzzing、静的解析、統合試験の結果と保証範囲を区別する。

Chrome・Firefox・Safari で、実際の画面操作・状態更新・認証連携を確認する。
採用した UI フレームワーク固有の再描画・ライフサイクルでも、重複操作や情報の混入を起こさないことを確認する。
通話用 React SDK に依存しない構成を認め、管理 UI のための不要な管理機能・共通抽象化を React SDK に追加しない。

結果には、ブラウザー・UI・サーバー・依存ライブラリのバージョン、権限設定、負荷、障害条件、更新間隔、期限・上限、検証範囲と観測結果を記録する。
画面構成、統計項目、更新間隔、履歴保持期間の具体値は、後続の設計で定める。
