# 共用する STUN メッセージ処理

STUN Binding、ICE、TURN で共用するメッセージ処理を定める。各用途の認証・トランザクション・状態管理は、その用途の仕様に従う。単独サーバーの動作は [Binding サービス](binding.md)で定める。

## 解析・検証・応答の判定

受信メッセージは、ヘッダー、メッセージ長、属性の長さと境界を検証する。
不正な長さによって、範囲外の読み取りや過大なメモリ確保を発生させない。

STUN の初期検証に失敗したメッセージ、未対応のメソッド、メソッドで許可されていないクラスは、応答せず破棄する。
必要な認証がある用途では、その検証後に未知の属性を処理する。
[RFC 8489 §6.3](https://www.rfc-editor.org/rfc/rfc8489.html#section-6.3)に従う。

未知の属性は、次のように扱う。

| 対象 | 処理 |
|---|---|
| Request の未知の必須属性 | 420（Unknown Attribute）と、対象を列挙した UNKNOWN-ATTRIBUTES を返す |
| Indication の未知の必須属性 | 応答せず破棄する |
| 未知の任意属性 | 無視する |

Indication に応答を返さない。
その他の要求内容の不備は、各メソッドと用途で定められたエラー処理に従う。
[RFC 8489 §6.3.1–6.3.2](https://www.rfc-editor.org/rfc/rfc8489.html#section-6.3.1)に従う。

## 自作範囲・既存実装の利用

STUN のプロトコル処理は Rust で実装する。

ヘッダー・属性を解析・検証し、応答を組み立てる処理を自作する。
未対応のメソッド・属性や不正なメッセージをどう扱うかも、自作するプロトコル処理で判定する。

これらの処理は自作し、完成済みの STUN 実装には委ねない。

ICE・TURN で使用する STUN メッセージの読み書きにも、同じプロトコル処理を利用する。
認証、再送、接続状態の管理は、それぞれの用途の仕様に従う。

## 受け入れ条件

| 試験対象 | 確認する結果 |
|---|---|
| 不正な入力 | ヘッダー、メッセージ長、属性長・境界の異常によって、範囲外アクセスや過大な資源確保が起きない。初期検証に失敗したメッセージには応答しない |
| 未対応のメソッド・クラス | 未対応のメソッドと、メソッドで許可されていないクラスを、応答せず破棄する |
| 未知の属性 | Request の未知の必須属性には 420 と UNKNOWN-ATTRIBUTES を返す。Indication の未知の必須属性は破棄する。未知の任意属性は無視する |
| Indication | 正常・異常のいずれも STUN 応答を返さない |

共通処理を利用する ICE・TURN の認証順序と用途固有の動作は、それぞれの仕様の受け入れ条件でも確認する。
