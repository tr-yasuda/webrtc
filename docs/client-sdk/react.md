# React SDK

Browser SDK の操作と状態を React 向けに提供する。通信・暗号処理と状態管理の中核は [Browser SDK](browser.md)に従い、React のライフサイクルと共有資源の所有を分けて扱う。

共通の前提・用語・利用場面は [共通仕様](../platform/overview.md) に従う。
参加端末間の暗号化と鍵管理は、[E2EE・鍵管理](../e2ee/key-management.md)に従う。

## 公開インターフェース

React SDK は Browser SDK を基盤とし、Hooks、Context、コンポーネントなど、React アプリケーションから利用するインターフェースを提供する。
WebRTC、Signaling、E2EE、配送・復旧の中核ロジックは Browser SDK を利用し、React SDK に重複実装しない。
公開する機能・状態・結果の意味は [Browser SDK](browser.md#公開インターフェース)の定義に従い、React SDK でも同じ意味で提供する。

## 自作範囲・既存実装の利用

Browser SDK と React SDK は TypeScript で実装する。
Browser SDK は通信と状態管理の中核を担う。React SDK は Hooks・Context・コンポーネントを実装し、状態変更の通知購読と、操作・結果の React 向けインターフェースを提供する。

React SDK は Browser SDK が管理する接続・鍵・配送状態を受け取り、表示に必要な形へ変換して提供する。変換後も元の完了条件と失敗理由を維持する。状態遷移や認可・暗号化・再接続の判断は Browser SDK に委ねる。

### 通知購読の終了と共有資源の所有

コンポーネントのアンマウントや Hooks の再実行でクリーンアップするときは、その通知購読や処理が所有する範囲だけを解放する。通知購読の解除だけで通話から退出したり、発行を停止したり、Browser SDK を終了したりしない。複数のコンポーネントが同じ Browser SDK を使う場合は、ほかの利用元が必要とする WebRTC 接続・メディアトラック・E2EE の鍵状態を維持する。

接続の生成・終了を担う所有者の責務は、通知購読のライフサイクルとは別に公開契約で定める。[React Strict Mode](https://react.dev/reference/react/StrictMode) による開発時の Effect の追加のセットアップ・クリーンアップでも、接続の重複や意図しない退出・発行停止が起きないようにする。具体的なインスタンス管理方法と React API の構成は後続の設計で決める。

### ライブラリの利用と資源管理

WebSocket、入力スキーマ検証、状態通知、計測、React との連携などには、既存の汎用ライブラリを利用できる。
完成済みの通話用クライアントライブラリや SFU 製品のクライアントライブラリに、プラットフォーム固有の通信・状態管理の中核を委ねない。
ライブラリによる解析成功や型付けだけで、通知の正当性・操作対象・更新順序を検証済みとは扱わない。

ブラウザーや既存ライブラリが管理する待機量・内部状態についても、利用可能な制御と計測を確認する。
Browser SDK が管理するキュー・通知・再試行・暗号処理待ちと合わせて資源を制限し、制御できない内部動作を無制限に利用する構成にしない。

Node.js や、React Native・Python・Go などへの対応と共通実装は、今回の要件に含めない。
具体的な API、Hooks、Context、コンポーネント、パッケージ構成は後続の設計で定める。

採用するライブラリのバージョン、設定、依存する機能と対応環境を記録する。
実装と検証は、[実装・検証の共通方針](../platform/verification.md#実装検証の共通方針)に従う。

## セキュリティ

React SDK は Browser SDK の検証結果と状態を利用し、認可・鍵状態の管理は Browser SDK が担う。秘密鍵・復号鍵は、[E2EE 仕様](../e2ee/key-management.md) の使用・保持・削除条件に従い、暗号処理に必要な Browser SDK 内部で扱う。

React SDK は状態を提供するとき、公開 Context、コンポーネントの props、表示用状態、その他の公開状態、アプリケーションの状態管理ライブラリ、開発者向けデバッグ機能に秘密鍵・復号鍵を露出させない。

アンマウントや Hooks・Effect の再実行時も、[通知購読の終了と共有資源の所有](#通知購読の終了と共有資源の所有) に従い、ほかの利用元が必要とする接続・トラック・鍵状態を維持する。

参加者名、論理チャネル名、エラー情報などの外部入力を、実行可能な HTML として描画しない。
React SDK が表示を提供する場合も、この条件を維持する。
Browser SDK の安全性を、同じページで動作する悪意あるスクリプトや侵害された参加端末から、平文・鍵を完全に隔離する保証とは扱わない。

操作待ち、通知待ち、再接続、暗号処理、未知の鍵を待つデータ、送達確認、通知購読には、件数・総メモリ量・保持期間などの上限を設ける。
重複通知や再試行によって上限を回避させない。
終了済みの処理結果で接続・送信・購読を復活させず、所有する資源を解放する。

ログ・診断・エラー報告には、認証情報、秘密鍵、復号鍵、メディア・データ本文、パケット全体を出力しない。
通常の状態通知には、対象と原因の判別に必要な情報だけを含める。
不要となった鍵・関連状態の保持と削除は E2EE 仕様に従い、Browser SDK の管理対象からの削除を参加端末内の全コピーの確実な消去とは扱わない。

## 受け入れ条件

実際の Browser SDK・React SDK と、C-Plane、Signaling、SFU、WebRTC Transport、STUN / TURN を組み合わせて検証する。
Chrome・Firefox・Safari について、通常動作に加え、権限拒否、接続切断、通知の欠落・重複・順序逆転、鍵更新、SFU 移行を確認する。

| 試験対象 | 確認する結果 |
|---|---|
| React の状態連携 | Browser SDK の状態と完了条件・失敗理由を維持する。描画や通知購読の更新で、独立した接続・鍵・配送状態を重複管理しない |
| React の共有資源 | 同じ Browser SDK を使う一部のコンポーネントのアンマウントや Hooks の再実行で、共有中の接続・トラック・鍵状態を解放しない |
| React Strict Mode | 開発時の Effect の再実行でも、重複接続、意図しない退出・発行停止、通知購読の蓄積を起こさない |
| 終了と所有関係 | Browser SDK 所有とアプリケーション所有の資源を区別する。終了処理の繰り返しや遅延結果で、誤解放や状態の復活を起こさない |
| 資源制限 | 操作・通知・暗号処理・鍵取得・再接続・送達確認の待機状態を有限に保つ。繰り返し操作や障害で保持状態が増え続けない |
| 秘密情報と表示 | 資格情報・鍵・本文を公開状態、React Context・props、状態管理、デバッグ、ログへ露出させない。外部入力を実行可能な HTML として描画しない |

Client SDK 共通の性能試験・検証方法・結果の記録は、[Browser SDK の検証条件](browser.md#共通の検証方法と結果の記録)に従う。React 固有の状態連携・所有関係とライフサイクルは、本書の受け入れ条件で確認する。
