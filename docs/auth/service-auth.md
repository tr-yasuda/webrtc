# 内部サービスの認証と権限の伝達

内部コンポーネント間の指示・通知について、認証、操作権限、対象と処理結果の対応を定める。共通の権限変更・失効条件は [認可仕様](authorization.md)に従う。

共通の前提・用語・利用場面は [共通仕様](../platform/overview.md)に従う。
各プロトコルの認証・状態管理は、それぞれのコンポーネント仕様に従う。
参加端末間の暗号化と鍵管理は、[E2EE・鍵管理](../e2ee/key-management.md)に従う。

## サービス認証と権限の伝達

### 指示元の認証と代理操作の認可

Signaling、D-Plane、その他の内部コンポーネントが要求や通知を受け取ると、まず送信元のサービスを確認し、対象と操作がそのサービスに許可されているかを判断する。内部ネットワークから届いたことや、利用者の参加 JWT が提示されたことだけでは、指示元を確認したとは扱わない。利用者の代理で行う処理に利用者・参加端末の権限が必要なら、サービス自身の権限に加えて、その権限も確認する。

別プロセス間では [共通のセキュリティ条件](../platform/security.md#共通のセキュリティ条件)に従って相互認証と通信の暗号化を行い、相手の識別情報を設定済みの信頼関係と許可範囲に照合する。サービス認証の具体的な方式は [方式選定](#方式選定)で決める。

同一プロセス内の呼び出しでも、呼び出し元が対象と操作を扱えるか、処理結果がどの要求に対応するかを確認する。確認にネットワーク通信や署名付きトークンを使うことは必須としない。この確認によって、別プロセスと同等の隔離や、同一プロセス内の任意のコード実行への保護は保証しない。具体的な実行方式と分離方法は後続の技術選定で判断する。

### 権限情報の受け渡しと適用

Signaling から D-Plane へ渡す権限情報は、次の内容を確認できるようにする。

| 情報 | 確認する内容 |
|---|---|
| 指示元 | どのサービスが指示し、その対象・操作を扱う権限があるか |
| 対象 | ルーム、参加端末、接続、発行・購読、Allocation など、どの資源に適用するか |
| 許可範囲 | 利用できる操作、用途、中継先などの制約 |
| 有効性 | いつまで利用でき、いつまでに再確認が必要か |
| 更新の対応 | どの権限状態や割り当てに対する更新・失効か |
| 処理の対応 | どの要求に対する受け付け・適用・停止・解放の結果か |

これらを一つのトークンやメッセージへ格納することは要求しない。
認証済みの通信、検証済みのデータ、管理する接続状態などを組み合わせて確認できるようにする。
受信した情報だけで、指示元が自身の許可範囲を拡大できないようにする。

D-Plane は、受け取った権限情報を検証した後、有効期限内であればパケットや操作のたびに Signaling へ問い合わせずに利用できる。

要求・更新・失効・完了通知は対象資源と処理に対応付ける。遅延・重複・順序逆転や再起動、接続の引き継ぎ、SFU 移行があっても、旧資源への指示を新しい資源に適用せず、すでに反映した失効や新しい接続・割り当てを古い情報で上書きしない。操作と失効が競合する場合は、既存仕様の確定順序に従う。

Signaling との通信や権限情報の取得に失敗した場合、確認済み情報を利用できる期限までは用途ごとの停止条件に従って既存通信を継続できる。必要な確認ができないまま期限に達した処理・通信を停止する。再接続・再試行だけでは期限を延長しない。具体的な停止条件は [認可仕様](authorization.md#有効期限権限変更失効の反映)に従う。

### 状態通知と処理結果の確認

D-Plane から状態通知や処理結果が届いたら、送信元、対象資源、現在の担当、元の要求との対応を確認する。通知が要求の受け付け、権限の適用、通信停止、資源解放のどの段階を示すかを確認し、停止・解放の完了はそれぞれの結果から判断する。結果が不明な場合は [共通の資源管理](../platform/resources.md#結果が不明な場合の照合と回収)に従って照合する。

### 資格情報の取り扱いと処理の上限

内部サービスの資格情報や権限伝達用の秘密情報を、Browser SDK・React SDK に渡さない。
サービス認証用の鍵・資格情報と、TURN・ICE・DTLS・E2EE の鍵・資格情報を無条件に共用しない。
ログや処理結果に秘密情報を含めない。

サービス認証、権限情報の配布、再確認、失効通知、結果照合にも、処理量・保持状態・待機時間の上限を設ける。

## 方式選定

Management と Signaling の公開 HTTP サーバーには Fastify を使用する。Management は WebSocket を扱わず、Signaling は `@fastify/websocket` を使用する。

Management から Signaling へ状態を変更させる指示には Pub/Sub コマンドバスを使い、結果も Pub/Sub の結果イベントで返す。Signaling への鍵配布にはサービス間認証を行った Management 内部 API を使う。読み取り専用照会には、サービス間認証を行った Signaling 内部照会 API を使う。サービス間認証の方式・識別情報の形式・Rust Worker の実行方式は、用途ごとに選定する。

サービス認証の選定では、実行環境に適した相互認証と、サービスごとの操作制限を行う方式を比較する。

## 自作範囲・既存実装の利用

認証連携、認可、資格情報の検証・更新・失効の制御は、TypeScript の Management・Signaling として実装する。
各プロトコルでの認証と権限の適用は、それぞれのコンポーネントが担う。
論理的な責務の分離と、実行プロセスの分離は同一視しない。

監査と資源管理では、必要な操作記録、処理量・保持状態の制限、結果不明からの照合を実装する。

鍵の保管、永続化、サービス認証、メッセージ配送、時刻管理、入力検証には、既存のライブラリや基盤を利用できる。
既存基盤が提供する順序・永続性・期限・障害回復の保証と、プラットフォーム側で補う条件を確認する。
同じ要件を満たす場合は、独自実装や追加コンポーネントを必要以上に増やさない。

既存実装の内部バッファ、キャッシュ、再試行、鍵取得、照会待ちも資源管理に含める。
ライブラリ自身の制限または組み込み側の制御により、必要な上限と期限を保証する。
失敗時に認証・認可を省略したり、期限切れの情報を使い続けたりする構成を採用しない。

採用する実装・基盤のバージョン、設定、依存機能、検証範囲を記録する。
セキュリティ修正を追跡し、更新時は影響する検証条件を再確認する。
実装と検証は、[実装・検証の共通方針](../platform/verification.md#実装検証の共通方針)に従う。

## セキュリティ

認証、権限付与、資格情報の発行・更新・失効、管理操作、状態取得、通知購読に、それぞれ必要な認証・認可を適用する。
認証済みの利用者・アプリケーション・内部サービスでも、対象資源と操作範囲を確認する。
資格情報の発行や権限変更によって、要求元の委任範囲を超える権限を与えない。

外部入力は、形式・サイズ・値・対象・更新順序を実行時に検証する。
署名済みの情報でも、その発行元が対象の利用者・ルーム・操作を扱えることを確認する。
表示名、メールアドレス、参加者 ID、参加端末 ID の一致だけで、利用者や接続の引き継ぎを許可しない。

Signaling から受け取った権限情報を利用するコンポーネントは、指示元・対象・操作・期限と、反映済みの変更を確認する。
参加 JWT を各コンポーネントで重複検証することは要求しない。
同一プロセス内の検証が保証する範囲は、[指示元の認証と代理操作の認可](#指示元の認証と代理操作の認可)に従う。

未認証要求、認証試行、資格情報の発行・更新、鍵取得、権限照会、失効通知、結果照合に、処理量・保持状態・待機時間の上限を設ける。
認証済みの要求にも適用し、再試行・重複要求や複数処理の並行実行で上限を回避させない。
過負荷時にも認証・認可を省略せず、失効期限を守るための処理を無制限の待機キューへ蓄積しない。

## 受け入れ条件

外部認証との連携処理、Management、Browser SDK、Signaling、D-Plane を組み合わせて検証する。
通常動作に加え、不正要求、権限変更、通知の欠落・重複・順序逆転、通信分断、時計のずれ、再起動、SFU 移行を発生させ、次を確認する。

| 試験対象 | 確認する結果 |
|---|---|
| サービス認証 | 指示元サービス、対象、操作権限、処理結果の対応を確認する。別プロセス間では相互認証と通信保護を適用する |
| 検証済み権限情報の利用 | D-Plane が参加 JWT を直接検証しない構成でも、指示元・対象・操作・期限・変更状態を確認する。毎回の Signaling 照会を前提としない |
| 資源上限・過負荷 | 未認証・認証済みの要求、並行処理、再試行でも上限を超えない。過負荷を理由に検証や失効期限を緩めない |

共通の前提は [認可仕様](authorization.md#前提)に従う。検証方法・認証全体の性能試験と結果の記録には、[共通検証条件](authorization.md#共通の検証方法と結果の記録)も適用する。
